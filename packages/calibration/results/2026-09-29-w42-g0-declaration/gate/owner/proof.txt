Closures (2026-09-30, the parent's ruling; run-owner.py step 8)

The ruling: a CLOSING named miss in the owner-run comparison is a pass, and its list shrinks at
the seal (floors come off by fix). The committed test compares MISSED_27_ROWS and L1's `MISSES`
with the lists it derives, in both directions, so a closure fails it exactly as a new miss would,
and vitest's JSON carries only a truncated message ("expected [ …(7) ] to deeply equal [ …(8) ]").
Step 8 therefore reads the lists rather than the message. Before each of those two assertions the
worktree's copy logs the derived and the recorded list to a scratch file; one added line each, no
assertion changed. A recorded entry the run no longer derives is a closure. The closing entries
are dropped from the copy, as the seal would drop them: the MISSED_27_ROWS line is deleted and
`MISSES` is filtered at its assertion. The test then runs again, and that second run is the run's
result. Closures are reported per run (summary.json `closures`) and never block.
