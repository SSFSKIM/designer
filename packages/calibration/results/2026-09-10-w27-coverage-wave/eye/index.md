# The 0.16.0 eye sheet

Two sheets, one per colour scheme, for the user's eye on the pending
`@vitreajs/vitrea-web` 0.16.0 cut — the nine changesets under `.changeset/`, which are W27's four
landed children (`docs/doperpowers/specs/2026-09-10-w27-coverage-wave.md`). Nothing in the runtime,
the demo or the packages was changed to make them.

| file | size | what it carries |
| --- | --- | --- |
| `eye-sheet-light.png` | 4720 × 7148 | the light material, five rows |
| `eye-sheet-dark.png` | 4720 × 7190 | the same five rows in the dark scheme |

Both sheets print a 2× ruler (200 device px = 100 CSS px) at the top. **Every panel is at native
pixels**: each was taken with Playwright's `scale: "device"` at `deviceScaleFactor: 2` and pasted
into the sheet at its captured size. Two stage panels in row 3 are *cropped* — never resampled —
and the label says so. The only derived images on either sheet are the five amplified difference
panels in row 5, each labelled `x 8 (derived)`.

## The machine, the browser and the adapter

- **Chromium 151.0.7922.34**, launched by Playwright 1.62.1 with `channel: "chromium"` (the full
  browser, headed) and `--enable-unsafe-webgpu --enable-features=Vulkan,WebGPU`. Never the headless
  shell, whose SwiftShader would have passed a CPU rasteriser off as the GPU tier.
- **WebGPU adapter: `apple` / `metal-3`**, `isFallbackAdapter: false`. Chromium masks `device` and
  `description` without an origin trial, so those two fields are empty in `capture-meta.json`; the
  vendor/architecture pair and the fallback flag are what the page can see.
- `devicePixelRatio` 2. macOS Reduce Transparency and Increase Contrast both **off**
  (`defaults read com.apple.universalaccess reduceTransparency` → `0`, `increaseContrast` → `0`);
  Playwright cannot emulate either, so the sheet would silently be a different material if they
  were on.
- Every group photographed reported `activeRenderer: "webgpu"` **before** its shot was taken. The
  capture script refuses the run otherwise — on no adapter, on a fallback adapter, or on any group
  that resolved to the CSS tier — and the resolved backend of every group is printed in the sheet's
  header and recorded in `capture-meta.json`.

## The exact commands

Pre-flight, because the GPU is shared:

```bash
pgrep -f 'compare.ts|sweep.ts|cost.mjs|capture.mjs|capture-web|VitreaReference|playwright'   # empty
lsof -i :5189                                                                                # clear
```

Then, from the worktree root (`main` at `12e90ad`):

```bash
pnpm install
pnpm -r build            # @vitrea/policy has no source alias in the demo's vite config, so the
                         # dev server cannot serve platform-web from source until it is built

# put the scratch harness back where vite serves it
mkdir -p apps/demo/eye apps/demo/src/eye
cp packages/calibration/results/2026-09-10-w27-coverage-wave/eye/harness/index.html apps/demo/eye/
cp packages/calibration/results/2026-09-10-w27-coverage-wave/eye/harness/{main.tsx,Eye.tsx,eye.css} \
   apps/demo/src/eye/
cp packages/calibration/results/2026-09-10-w27-coverage-wave/eye/harness/capture.mjs \
   apps/demo/eye-capture.mjs

pnpm --filter demo exec vite --port 5189 --strictPort &      # serves /, /playground/ and /eye/
cd apps/demo && node eye-capture.mjs                          # writes eye/panels/**, eye/panels/meta.json
cd ../../packages/calibration/results/2026-09-10-w27-coverage-wave/eye
/Users/new/.claude/jobs/5c70e47f/tmp/venv/bin/python compose.py   # writes the two sheets
```

Stop the vite server afterwards. `panels/` is **not committed** — it is the raw capture, the way
`packages/calibration/web-captures/` is not committed either, and it is regenerated by the command
above. `panels/meta.json` is committed beside this file as `capture-meta.json`: the adapter, the
Chromium version, every group's resolved state, the per-frame channel readings and the site's own
readouts.

The demo e2e suite was deliberately **not** run for this: `contrast.spec.ts`'s
"the plates' labels hold the large-text floor" can eat 24 s of its 30 s budget under load, and a
timeout there is not a reading.

## Why a harness, and what is live

The sheet photographs the shipped demo wherever the shipped demo has the feature on screen, and a
scratch harness (`harness/`, served at `/eye/`) where it does not. Which is which:

| feature | live instance in the shipped artefacts | on the sheet |
| --- | --- | --- |
| toolbar split | **yes** — `/playground/`: `GlassToolbarSpacer kind="flexible"` + `ActionsMenu sharedBackground="hidden"` (`apps/demo/src/App.tsx`) | live panel on the light sheet; the split-beside-unsplit pair is the harness, because no page has the unsplit counterpart |
| `present` / `Glass.identity` | **yes** — `/playground/`: the "Dismiss glass" button on the `dom-plate` | live panels on the light sheet; the six-frame strip is the harness, which is where the frame loop can be driven by hand |
| `GlassMorph transition="materialize"` | **yes** — `/playground/`: the "Materialize the Actions menu" checkbox | harness, for the same reason (and to put it beside `matchedGeometry` at equal times) |
| the page-content material | **yes** — the site's `/#page`, beside `/#material` | **live**, both schemes |
| the lens answering the pointer | **yes** — every interactive control on both pages | harness, so the two sampling backends sit side by side on one capsule over the same kind of structure |
| tinted `GlassButton` / `GlassIconButton` | **no** | harness |
| `GlassGroup tint` | **no** | harness |
| the four ink levels | **no** | harness |

The three "no" rows are a finding, not a preference. `grep -rn 'tint=' apps/` hits only
`apps/demo/src/laws/LawsStage.tsx` and `apps/demo/src/site/Stage.tsx`, both on a `GlassSurface`;
nothing in `apps/` names `--vitrea-foreground-secondary`, `-tertiary` or `-quaternary`. So W27a's
four user-facing items have a README paragraph and a public prop but **no live instance a reader can
operate**, which is the wave's Parent-Level Acceptance #2. The harness is scratch and is not part of
the demo; its source is committed here so the sheet can be remade, and `/eye/` does not exist on the
deployed site.

The harness mounts `<GlassRoot renderer="webgpu" autoStart={false}>` under `?stepped=1` and the
capture script drives `root.runFrame(clock)` and `ticker.advance(dt)` by hand. That is why the times
printed under the transition frames are the frames' own times — they are not "the moment a
screenshot was requested", and nothing about the shipped durations or easings was changed to get
them. Chromium's virtual-time policy was tried first and rejected: the motion drivers follow the
compositor's frame clock, not `performance.now()`, so a virtual-time step ran the whole transition
between two shots.

## Row by row

1. **A toolbar splits its shared background** — `a-toolbar-splits-its-background.md`.
   Split beside unsplit over a structured ground. The spacer's `min-width` measured **24 px** on
   this run (nominal policy, Reduce Transparency off); it is derived through
   `samplingPaddingFor({ members, material })`, not written down. Also on the light sheet: the
   playground's own split bar.
2. **Tinted buttons, a tinted group, four ink levels** — `buttons-can-be-tinted.md`,
   `a-group-carries-its-seed.md`, `four-named-ink-levels.md`, `the-material-decides-its-own-ink.md`.
   Four `GlassButton`s (two full-strength tints, one at 50 % alpha, one untinted), a
   `GlassGroup tint="#30d158"` whose second member clears it with `tint={null}`, and one surface
   carrying all four ink tokens as text.
3. **The WebGPU material over ordinary page content** — `page-content-gets-the-material.md`.
   The live site at `/#page` (`configuredSource: dom`, `css-backdrop`, `refraction: approximate`,
   `analysis: none`) beside `/#material` (`texture`, `gpu-texture`, `refraction: true`,
   `analysis: exact`), and beside the native stack fixture at the matching 2× scale, read-only.
4. **Authored presence, and the two morph transitions** — `the-material-can-leave-in-place.md`.
   Six frames across `present={true} → {false}` at 0/40/80/120/160/240 ms, each printing
   `--vitrea-materialization` and `getComputedStyle(host).opacity`, which reads `1` on every frame
   including presence 0. Then `transition="materialize"` against `matchedGeometry`, six frames each
   at 0/60/120/180/260/420 ms. On the light sheet, the playground's live plate before and after its
   glass leaves — the label the host keeps is drawn in the material's own ink, which is the X9 limit
   named in claims §5.132 §6, not a defect.
5. **The lens answers the pointer** — `the-lens-answers-the-pointer.md`. One capsule at rest,
   hovered and pressed, on each sampling backend, with `--vitrea-lens` printed under each frame:
   exactly `1.0000`, `1.0600`, `1.1400`, the values the renderer used to clamp away. Each state is
   followed by its difference from rest, amplified ×8, because the movement is small by design.

## What is not on the sheets

- **`recede-keeps-strength.md` (W27c G1) has nothing to photograph.** It publishes the
  scheme-indexed `recededMaterialProfile` difference documents, identity by default; the activation
  observer and the public `windowActivation` root option are W27c G2, which the wave's stopping
  point did not dispatch. No page can be put into the inactive pose, so the changeset appears on
  neither sheet.
- **`the-material-decides-its-own-ink.md` has no panel of its own.** It is visible as the ink on
  every untinted surface on both sheets — most plainly on the dark sheet, where untinted plates
  carry the ink the material's level decided rather than the one the colour scheme would have
  picked — but there is no before/after, because the old behaviour is gone and this cut is not
  built with it.
- **The dark sheet carries no playground panels.** The playground's `<GlassRoot>` takes the
  binding's default `colorScheme="light"` and reads no `?scheme=` parameter, so there is no
  dark-material playground to photograph. Its live panels appear on the light sheet only.
- **The dark native stack panel is the checkerboard, not the photo.** `apple-macos-26.5-2x-dark-standard`
  carries only `checkerboard__glass-over-glass__{rest,inactive}`; there is no
  `photo__glass-over-glass` at 2× dark. The light sheet uses the photo stack as asked.
- **The native panel is not a diff.** It is a different scene at the same scale, there for the
  overlay's character. The measured comparison lives in `results/matrix.json` and the claims ledger,
  not here.
- **The morphs open only.** No closing strip, and no Reduced Motion strip (both tiers step material
  presence rather than animating it under Reduced Motion, which a still sheet cannot show).
- **`tint-mixing` does not appear, and should not.** It was checked rather than assumed: a run that
  collected every console diagnostic raised `quaternary-ink-on-thin-material` twelve times and
  `tint-mixing` zero times. A group with no seed of its own and one tinted member carries one seed;
  the diagnostic is for two. The twelve quaternary findings are correct and are the harness's own
  doing — the ink card names `--vitrea-foreground-quaternary` while 44 px controls sit on the same
  page, and that finding is document-level by design.
- **CSS-tier panels.** The wave's tier boundary (X1) states every measured claim against the WebGPU
  tier, and the capture refuses any group that did not reach it; `?renderer=css` on either page is
  where the fallback can be looked at.
