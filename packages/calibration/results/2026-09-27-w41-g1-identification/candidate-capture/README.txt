W41 G1 — web-only E3 capture orchestration preparation (c9a §5.192)
=================================================================

This is an adapter over baseline.project and the finalized G1 exposure runner's
runtime source inventory, committed-input checks, document decoding and validate_domain.
It does not implement a third projection/scoring engine. It never constructs a
native Reader, imports the candidate scorer, touches a receipt, scores survival,
uses the canonical matrix CLI or changes candidate coefficients. Importing the
baseline helpers does not call their native transfer operation.

The input frontier is BOTH committed, complete shipped freezes: 536 calibration /
validation cells and 64 blind public holdout WEB cells. Public metadata inspection
of that held-out membership is authorized by charter v2.3; it is not a native
holdout read. Assembly additionally requires byte-for-byte integrated runtime and
scratch documents from reviewed leaf commits775a1f26+64dbad42. reviewed-inputs.json
was extracted from the isolated branch's final commit, not generated from whatever
primary source happens to be present. Only light-receded has E3 enabled; the other
three candidate documents must remain literal shipped byte copies.

The assembly stores a pre-render seal, policy-runtime snapshots, a shipped map
with content-addressed payloads, the full public metadata/backdrop/source pins,
and a source-derived regular/presence1 attestation. It creates NO candidate pixels
or success flags. That entire assembly must be committed before any capture.
The pre-capture source frontier retains every runtime SOURCE_ROOTS file and the
package/config inventory from runner.sources, including newly added runtime files.
Its Python instrument frontier is only the driver's executed transitive repository
imports (including the driver itself and unregistered inherited boundary modules),
not unrelated G1 stroke, CSS, sheets or candidate-scorer sources. Added imported
helpers and edits to imported bytes invalidate the seal; unrelated instrument edits
and additions do not. The final exposure runner keeps its full source frontier.
Every later process verifies the same seal, current source membership/bytes,
policy artifacts and committed inputs. The PNG/report producer remains the
unchanged capture-web.ts (channel chromium), requested WebGPU and texture mode,
with fallback disabled. Actual renderer/sampling, nominal policy, scale, colour
scheme, deterministic repeat, material pair and root-active candidate receded
pose are checked through the reviewed runner.validate_domain, not caller claims.
Regular and full presence are source-derived, explicitly not observations in the
report. The attestation follows registration → published materialization channel
→ bridge → instance lane17 → field union/presence target → optics consumption.
