The one-begun-attempt clause and all scientific membership/closure/veto rules stay

Before begin
------------
After frozen-input verification, production creates the attempt output directory
and obtains ONE fresh X6 reading. x6-prebegin.json durably records it. A failed
fact or observer error returns without constructing a Receipt. There is no wait
here and no browser or native access. A failed prebegin attempt leaves its output
evidence intact; use a new output destination for a later preflight, never overwrite
that reading. The original production receipt path is not changed.

Inside the single receipt
-------------------------
One X6WaitBudget instance is shared by every candidate/profile CaptureRequest.
Elapsed time inside X6 guards—including observation, snapshot verification,
evidence persistence and bounded sleep—is accumulated. Browser capture and
subsequent projection/scoring time between guards are not included. Each failed
facts reading is persisted as waiting, followed by a sleep of at most30seconds
and another fresh reading. Sleep is shortened to the remaining shared budget.
Passing facts never reset the budget for the next profile or candidate.

Every observation has its own exclusive, file-and-directory-fsynced record:
  <candidate-output>/x6-<profile>-observation-0001.json
The record retains raw facts, recomputed verdict, observation sequence and elapsed
cumulative guard time. The terminal x6-<profile>.json summarizes the last passing,
deadline or snapshot-error observation; it never overwrites an earlier observation.
The output remains inside the existing attempt directory, never the source tree.

When facts pass within the budget, the full frozen manifest/source/runtime/payload
snapshot is reverified before launch. Mutation refuses, with a snapshot-error
record; it is not converted into a failed machine fact or another polling cycle.
Observer exceptions retain raw error details and unknown observation/verdict when
nothing returned, then fail closed. Persistence errors prevent launch. Failed
machine facts can wait only until the shared3600-second budget is exhausted;
then the attempt refuses/spends under the existing receipt path. No failed browser
capture or native score is retried by this waiting mechanism.
