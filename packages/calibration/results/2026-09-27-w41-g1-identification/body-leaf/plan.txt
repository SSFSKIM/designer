CSS mirror route (step9, not now)
Use the same profile fields, never the old BODY_CHROMA_RETENTION=0 decline as
proof about E3. CSS filter functions operate in sRGB; saturate uses weights
(.213,.715,.072), NOT the E3 (.2126,.7152,.0722). A uniform fixed-L projection can
use saturate(s) plus a neutral rgba plate: pre-clamp coefficient g=(1-alpha)*s.
With E3 W and CSS Ws, a particular uniform x needs offset F(W.x)-g*(W.x);
the CSS affine offset is (1-alpha-g)*(Ws.x)+alpha*n. Choose a realizable n/alpha
and derive s; verify the actual CSS matrix and intermediate clipping, not only
this affine algebra. The brightening white-plate choice is
 alpha=[F(L)-g*L-(1-g)*Ls]/(255-Ls), s=g/(1-alpha), where Ls=Ws.x;
use an explicitly derived darkening projection rather than dividing by zero or
assuming white can darken. These formulas are not an adopted CSS mapping.
Saturation before the plate can clip bridge channels; a filter cannot make its
coefficients depend on EACH pixel's encoded L on a photograph. Group hints/
means are not an E3 local input substitute. Measure uniform cells and structured
residuals in Chromium only after authorized capture; if no CSS derivation meets
the bound, retain and quantify the decline under Decision Log4. Do not add S1/S2
or fit new CSS family parameters to disguise that limitation.
The runtime has one document-wide CSS mapping selected in root.ts, not a separate
receded mapping; readRecededProfileFile forbids a receded cssTierMapping. Route
pose-specific projected optics from the actual posed material fields, or leave
CSS unchanged and record its projection residual; do not globally change active
CSS to approximate a light-receded-only candidate.
Primary reference checked during prep: https://www.w3.org/TR/filter-effects-1/
sections FilterProperty, funcdef-filter-saturate, feColorMatrixElement and
FilterPrimitivesOverviewIntro (sRGB, saturate matrix, chained/clamped primitives).
No live browser or CSS measurement was performed.
