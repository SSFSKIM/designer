## Purpose

Every native pixel vitrea has ever been measured against was captured on macOS 26.5.2. Apple
shipped macOS 27 on 2026-09-14 and says the material changed underneath every app without a
recompile: stronger diffusion of complex content, a darkened edge, brighter specular highlights,
more uniform refraction, a common tighter window corner, edge-to-edge sidebars, uniform toolbars,
and a user-facing transparency slider whose default is the centre of a range from ultraclear to
fully tinted. The project's goal is the least possible gap between vitrea and Apple's material, and
from 2026-09-14 "Apple's material" is what a Mac on 27 draws. This wave moves the reference.

It does so in the order the fidelity discipline requires. First the 26.5 evidence is frozen and
proven untouched. Then Apple's 27 material is captured under new keys with every axis that can move
a pixel attested per run, including the two 27 introduces (the slider; Show Borders decoupled from
Increase Contrast). Then what 27 changed is **measured native against native**, cell by cell,
against a noise bar taken from the 26.5 bed's own run-to-run behaviour, and written into the ledger
before any line of vitrea moves — so the refit that follows is a response to a measurement, not to
a press release. Only then is the material refit, on the WebGPU tier with the CSS tier derived in
the same wave, under 27 profile documents, judged by bounds declared before the read, with the
holdout read once. The 26.5 documents, fixtures and rows stay as committed evidence; the 26.5
bounds keep running against the frozen 26.5 rows, which is the proof that nothing there moved.

What this wave does **not** do: it does not identify the abscissa (W28 §Deferred; re-runnable on
the 27 bed afterwards), it does not build the motion-metrics harness (next), and it does not
capture the slider's two ends as evidence classes unless G0 shows the slider moves the cells at all
and the user rules them in.

5. **Which material a page gets is a stated decision.** The runtime's default profile after this

## Grounding Baseline (main at `6ac184c1`, 0.18.0 published)

- **The 26.5 bed.** Six profile directories, 619 fixture PNGs (164 / 164 light standard 1x / 2x,
  115 / 114 dark standard, 32 increased-contrast, 30 reduced-transparency; 277 of them inactive),
  32 background PNGs, one `manifest.json` whose `hardware` block reads macOS 26.5.2 build 25F84,
  MacOSX26.5.sdk, Xcode 26.6 17F113, Mac14,12 M2 Pro. `results/matrix.json` schema 5, 1,107 rows
  (563 light standard, 437 dark standard, 55 IC, 52 RT; probe 720, calibration 264, validation 64,
  holdout 59). `scenes.json` version 5: 168 scenes, split calibration 37 / validation 12 / holdout 20
  / recorded 8 / probe 91.
- **The appearance setting the 26.5 bed was captured under.** macOS 26 offers Liquid Glass as
  *Clear* or *Tinted* in System Settings › Appearance. No preference key for it exists in any plist
  under `~/Library/Preferences` on the capture machine (searched 2026-09-16, before the update), which
  is what a never-touched default leaves behind; the bed therefore stands at Apple's 26 default. The
  setting itself was never recorded in a manifest. **Recorded here as an inference from the absence
  of a key, not as an attestation**; the user can confirm the pane's state before updating.
- **What is coupled to 26.5.** One hard gate: `results/2026-09-11-w27-26.5-run/run-sitting.sh:50`
  refuses any `sw_vers` not `26.5*`. The Swift harness has no `#available`, reads no OS version
  except to *record* it (`Manifest.swift`), and validates the a11y, scale and scheme tokens of a
  profile key against the machine but **never the OS token** — nothing in the harness would stop a
  27 machine writing into a 26.5 directory. Profile keys are literals in `scenes.json` (six of
  them), copied verbatim into fixture directory names and manifests; the material profile documents
  are named by convention and passed by path (`--material-profile`), with three consumers that
  hard-code the 26.5 filename (`platform-web/src/dark-profile.ts`, two calibration tests). Tests
  pinning 26.5 names: `adopted-thresholds` (74 hits: floors, per-profile bounds, cell counts,
  36 `PREDICATE_EXCLUDES` entries), `scene-matrix` (16), `tuned-profiles`, `report`, `profile-key`,
  `vibrancy` (asserts the build set is exactly `Version 26.5.2 (Build 25F84)`), five more with one
  or two each; the demo's site, calibration and vite config name the two fixture directories it
  ships and `pages.yml:73` asserts the light one exists.
- **The key grammar.** `PROFILE_KEY_PATTERN` accepts `\d+\.\d+` for the OS token, so
  `apple-macos-27.0-…` parses today and a bare `27` would not. The grammar ends at the a11y token:
  it has **no slot for the slider** and its `a11yMode` enum cannot express Show Borders decoupled
  from Increase Contrast (c9a §5.134 already names both).
- **The granted bundle.** `apps/reference-apple/build/VitreaReference.app` is not in git; built by
  `build.sh` with plain `swiftc`, `-target arm64-apple-macos26.0`, MacOSX26.5.sdk, ad-hoc signed,
  bundle id `dev.vitrea.reference-apple`. Screen Recording is granted to that signature and a rebuild
  invalidates the grant until the user toggles it (README, tracker); a recorded denial suppresses
  the prompt, so a broken grant fails silently. Its ScreenCaptureKit calls are all ≤ macOS 14 APIs,
  none deprecated; deployment target 26.0 launches on 27. **It can be reused byte-for-byte**, and
  `VITREA_BUILD_OUT` builds a side bundle beside it for any experiment.
- **The scientific risk of reuse.** The bundle links the 26.5 SDK, and macOS routinely gates
  appearance changes on the linked SDK version. Apple's statement is that existing apps get the 27
  material without recompiling; if any part of it is SDK-gated, a bed captured with the granted
  bundle would be labelled 27 and draw 26-era glass. Settled by one comparison (G0).
- **What the metrics can and cannot do.** `measureCell` is native-against-web by construction;
  `ResultCellKey` requires a `WebCell`, so the result matrix cannot hold a native-against-native
  row. The primitives are image-pair generic (`ssim`, `oklabDeltaE`, `silhouetteIoU`,
  `contourDistance`); `cli/tier-delta.ts` is the precedent for a pair diff with no fixture in it;
  `src/plurality.ts` classifies byte-level run-to-run differences as noise or structural. A
  native-delta driver has to be written (G2) and its rows live beside the matrix, not in it.
- **Capture cost, from the 26.5 record.** The harness runs 9.5 s per cell. W27c's 188-cell round
  was 29.8 min per run, 3.5 h at the seven-run bar before attempt loss, 4.4 h wall in `sitting.md`.
  A full 27 bed of 624 declared cells is about 99 min per run; at seven runs ≈ 11.5 h before the
  record's 1.3–2.5× attempt-loss, so **15–29 h of unattended machine time** across passes, each
  pass one scale × one accessibility mode × one pose; the two accessibility passes need the user to
  flip System Settings. The cells whose 26.5 bar was lower than seven (G1 reads it from
  `bedProvenance`) cost proportionally less.
- **The machine.** Mac14,12 (M2 Pro, Apple silicon, so 27-eligible), macOS 26.5.2, Xcode 26.6.
  Software Update offers macOS 27 build **26A428** (the same build as the 2026-09-09 RC) and macOS
  26.7. Reduce Transparency and Increase Contrast read 0 / 0 on 2026-09-16.
- **Public record of the change** (all secondary except the WWDC26 State of the Union and Apple's
  macOS page; see the research note): darkened edge, brighter speculars, stronger diffusion, more
  uniform refraction; window corners common and tighter (secondary: 20 pt from 26); sidebars
  edge-to-edge with colour; uniform toolbars on scroll; window shadows separating active from
  inactive more strongly; the slider at System Settings › Appearance, centred by default, asked for
  during installation, reported by reviewers to move menus, toolbars and sidebars and **nothing
  reported about `.glassEffect()` surfaces**; no public API or defaults key for its position;
  `NSGlassEffectView.effectIsInteractive` the one new glass symbol; `appearsActive` the environment
  value for the inactive appearance; no ScreenCaptureKit acquisition change in the RC notes.

## Design (advisory unless marked)

- **Keys.** [binding] `apple-macos-27.0-<scale>x-<scheme>-<a11y>`, the OS token equal to
  `sw_vers -productVersion` major.minor read at the run's opening. The shell gate that refused
  non-26.5 becomes a gate that refuses non-27.0 for this bed, and `materialize` refuses a manifest
  whose `hardware.osVersion` does not begin with the key's token — the check the harness never
  had, added in TypeScript so the granted bundle is not rebuilt for it.
- **The slider.** [binding] G0 measures whether it moves the harness's cells at all, before the
  key grammar is touched. If it does not move `.glassEffect()` surfaces, the position is attested in
  the manifest (a required field, read however G0 finds it can be read — a defaults key found by
  diffing before and after moving it, or a screenshot of the pane filed with the run) and the key
  stays as above. If it does, the grammar gains a trailing token and the bed is captured at the
  default (centre) position only; the ends are evidence classes for the user to rule in or out.
  Either way the 27 bed is captured at the centre, which is what a Mac shows by default and what a
  web page should match.
- **Show Borders.** Off and attested in every run; not an evidence class in this wave (Deferred).
- **The native delta driver** (G2). A CLI shaped like `tier-delta.ts` over two fixture
  directories, writing `results/<dir>/native-delta.json` rows keyed `{ profileKey27, profileKey26,
  sceneId }`, with the same metric primitives the fidelity read uses and the rim-band and highlight
  reads from the 26.5 waves (W23, W24). The noise bar is taken from the 26.5 plurality record
  (run-to-run maxDelta / changedPx on the same cell) so "moved" means "moved more than 26.5 moved
  against itself".
- **The refit** (G3) is chartered from G2's reading, not from this document: which laws moved
  (rim/edge darkening, highlight amplitude, scatter/diffusion, tone response, corner geometry) is a
  finding, and the child's acceptance names them. The mechanism precommit rule from W28 applies: no
  new operator is added to the material because a review article names an effect; an operator is
  added when the native delta shows a structure the existing profile cannot fit.
- **The default target** (clause 5) is the user's; the parent's recommendation is 27 by default
  with the 26.5 documents kept in `profiles/` as evidence and selectable through the existing
  `applyMaterialProfile` path, since every Mac that installs the update draws 27 and a page has no
  OS to follow.
