## Purpose

v1 shipped the material with its fidelity claim held to exactly what was
measured: 1× cells, two profiles, a size channel without its laws, no
author-facing tint, and a layer rule stated in prose but enforced nowhere. This
wave widens what the claim covers (the measurement bed first — scale and
accessibility profiles), then closes the three highest-value absences the
coverage matrix ruled as the round's openers (#33(a)), and clears the recorded
seed backlog so the next cut starts clean. The ultimate-goal frame: every child
either widens the measured-fidelity moat (the thing no competitor in the
verified prior art has) or removes a trap a real adopter would hit.

## Parent-Level Acceptance

Observable state that closes the wave as a whole, verified at recomposition in
the shipped artifacts:

1. The fidelity claim covers **2× and both accessibility profiles**: profile
   files and capture matrices exist for the new keys, thresholds are adopted
   and enforced in-suite for them, and the committed 1× matrix is re-baselined
   under recorded capture conditions (its accepted ≤1.5e-4 staleness resolved).
2. A thick and a thin surface over the same backdrop differ the way Apple's
   do: the **size law** couples the material's thickness-derived facets, with
   the coupling fitted against the matrix and holdout-checked.
3. An author can **tint** a surface through a supported API and the result
   remains glass (not flat fill), with a measured claim of its own.
4. Putting glass where the layer model forbids it (glass nested inside
   glass's content) produces a **dev-mode diagnostic naming the rule**, and
   the layer model is documented where an adopter reads.
5. The seed backlog items W6 carries are closed or explicitly re-recorded with
   reasons; `pnpm run ci` and all Playwright suites green; the wave ships as a
   minor release with the demo showing the new capabilities.

## Design

Thin by intake shape — this is an uncoupled bundle; each child designs its own
means. What the joint view settles is graded binding below and in the
contracts.

- **[binding — user ruling 2026-08-28] The reference stays macOS 26.5.** The
  capture machine is this Mac mini (macOS 26.5), driven into a HiDPI scaled
  mode for the 2× keys — the user confirmed the match and chose this over
  updating the Retina MacBook (which runs macOS 15, pre-glass). Every existing
  threshold and fitted constant therefore stays valid; OS 27 reference
  migration stays Deferred.
- **[binding — cut-level ruling] W1 is the bed; W2 and W3 tune only against
  W1's matrix.** Calibration-tuned work against the stale or 1×-only matrix
  would re-create exactly the blind-spot class that produced the corner-hook
  defect (#40).
- **[binding — cut-level ruling] Motion metrics are out of this wave.** The
  native side has no declarative pressed pose; frame sequences need an
  input-driving capture harness that is its own future initiative (Deferred).
- Advisory: the wave probably ships as **0.2.0** at recomposition (new public
  API in W3/W5); a mid-wave patch release is legitimate if W6 lands long
  before the calibration children.

## Risks & Mitigations

- **HiDPI capture ≠ Retina capture.** A scaled mode renders at 2× into a
  panel that downsamples for display; ScreenCaptureKit reads the backing
  store, so captures should be true 2× — but this is exactly what W1's G1
  experiment must prove, not assume. Mitigation: G1 verifies pixel dimensions
  and `backingScaleFactor` from the harness's own probe before any matrix
  run; if the panel's backing store disappoints, the fallback (MacBook on
  macOS 26) returns to the user with the reference-version question attached.
- **Accessibility toggles change the whole desktop.** W1's capture sessions
  announce before flipping display mode or accessibility settings and restore
  after; the harness's refuse-mislabeled-keys guard is the backstop.
- **Two children in one working tree.** X3's re-read rule, plus per-child
  file-scoped commits (`git add` by name, never `-A`).

### W9 — backdrop tone as a function of surface size (the next wave's opener)

Chartered 2026-09-01 by Decision Log 22, grounded in claims §5.26 and owning
every one of the thirty-three rows §5.27 floored. **Not** a deferral in the sense
the list above uses: this is the next wave's first question, and the flip landed
in a state that only makes sense if it is answered.

**The measurement it starts from.** Similarity against the reference degrades
monotonically with surface area, but only over a backdrop with high spatial
frequency. Over a photograph the GPU tier is flat at 0.99 across a twenty-two-fold
range of area; over a checkerboard it falls from 0.993 to 0.831, and on the CSS
tier to 0.688 against a 0.90 bound. Solid backdrops are unaffected. The
cross-renderer axis reads the same mechanism: a tinted capsule over the
checkerboard puts the two tiers 64% apart on interior level.

**What it must not assume.** That this is the CSS tier's known coarseness. That
tier is worse — one backdrop mean per source through a non-linear tone map, a
limit `backdrop-tone.ts` documents and whose referee has now ruled against it —
but the GPU tier reads a local neighbourhood and still misses. Locality alone is
therefore not the remedy, and "restate the cover-fit mapping in platform-web" is
not what the evidence points to.

**What would count as done.** The thirty-three floors in §5.27 removed rather
than re-pinned, each with its adopted bound restored as a met claim. A floor that
is merely re-pinned higher is progress and should be recorded as such, but it is
not the charter being discharged.

**One standing caution.** `sizeOcclusionGain` was fitted this round and adopted at
0.05, and the residual remained size-monotonic after it. A second scalar size term
is the obvious next move and is probably the wrong one; the evidence says the
mechanism is in how the backdrop is *sampled*, not in how much a gain scales what
was sampled.

**Explicitly out of scope:** WebGL2 tier; topology-changing morphs (standing
parent exclusions, unchanged).

**External, user-held (not children):** the Gecko manual pass (conformance
rows fail closed meanwhile); filing the drafted Chromium bug report.

**Added 2026-09-03 (claims §5.48) — the 2x lens study.** The rim's curvature,
the sharper centre and the haze the eye sees against the 2x fixtures and the
metrics do not: measure the displacement/magnification field cell by cell,

referee by eye as well as by number. Recommended ahead of the two-layer CSS
body.

### What this wave actually was

Chartered as coverage-plus-features (bed widening, size law, tint,
diagnostics, API batch), it became, through discovery, an instrument
wave. Five times an attestation gate caught the reference itself
misbehaving, and each time the response was structural rather than
local: the settledness defect became the convergence loop; the
inactive-material discovery (the project's entire capture history had
recorded the never-key pose) became per-cell presentedActive and tint
attestation; the outer-shadow discovery became W8 on both tiers and the
two-axis instrument; the plurality observation became, on adequate
sampling, the two-state material finding — over half the bed draws one
of two settled appearances per cell — and then the capture-protocol
doctrine (unlocked + wake-asserted + idle-bounded, proven per cell;
seventeen runs for 95% confidence; the six-second reset; unanimity or
explicit frequency-settling); and the profile-SHA finding became the
resolved-material fingerprint. The three-run rule every earlier bed was
accepted on bought roughly a coin flip of noticing a second state; that
arithmetic, not any single defect, is the wave's deepest lesson.

### Lessons worth carrying

- A completion line is not a result: two "COMPLETE" phases each hid a
  void run that only the per-cell attestation audit caught. A phase is
  complete when the audit passes.
- A vote assumes one truth plus noise; a system with two stable states
  needs the disagreement's *structure* checked before any majority is
  taken.
- Guards must be written so that matching cannot read as failure (the
  `grep -q`/SIGPIPE bug silently disabled the lock guard for most of a
  campaign) and provenance must name the resolved artifact, not the
  input file.
- Fixing a falsified constant against the cells that falsified it is the
  one move the discipline forbids; three times this wave the honest
  answer was new evidence (a re-capture, new spans, a study) rather
  than a refit.
- Stale build output produces convincing false failures twice over; the
  CI gap (no Playwright in `pnpm run ci`) is recorded tech debt.

- 2026-08-31 (W8 — the outer shadow, appended by that child; no other section of
  this spec touched). **The facet is implemented on both tiers, behind the
  material profile seam, with the mechanism measured from the active bed's own
  fixtures and the constants left PROVISIONAL for the cascade (X1).**

  **The mechanism, and how well it holds.** The reference's shadow is the
  component's OWN rounded silhouette, outset by a spread, translated down by an
  offset, blurred by a Gaussian, and applied as a multiplicative occlusion:
  `L_out = L_backdrop × (1 − occlusion · Φ(−sd/σ))`. Fitted in two dimensions
  against the outside-component region of the native fixtures, that model
  reproduces the reference to an **RMS of 0.0021 in occlusion over 142,550
  pixels** on the finest cell (2× photo capsule), and 0.0013–0.0043 on every
  other well-conditioned cell — about 1% of the facet's own amplitude.
  Multiplicativity is not assumed: mirrored pixel pairs either side of a capsule
  over the `photo` backdrop see one shadow over two different backdrop
  luminances, and the darkening's ratio tracks the backdrop's ratio to **4.5%**
  where a constant-subtraction model misses by **79%** of the signal.

  **The lengths are in points, and they are span-invariant.** σ = 15.55, offset =
  7.95, spread = +3.10 CSS px. The 2× bed measures 31.05 / 15.83 / 6.58 device
  px — exact doubling — and the amplitude is scale-free to four decimals
  (0.3259 at 1× against 0.3258 at 2×, independently captured). Across spans of
  32, 44, 96 and 160 px the fitted σ stays inside 15.4…15.9 and the offset inside
  6.9…8.1. **Only the amplitude is a candidate for span coupling**, and it ships
  uncoupled: over `photo` it falls 0.326 → 0.196 between span 44 and 96 while
  over `light-solid` it RISES 0.123 → 0.198, and the dark scheme rises 0.060 →
  0.177 → 0.274 across 44/96/160. One monotone gain on one thickness curve cannot
  be all three; the seam exists at the identity, which is `sizeOcclusionGain`'s
  own precedent and Decision Log 13's finding in a second place.

  **Both tiers paint it identically, and the CSS tier's version is not an
  approximation of the mechanism.** A `box-shadow` is a constant colour
  composited source-over — which IS a multiply when the colour is black, because
  `(1−α)·backdrop + α·0` is `backdrop·(1−α)`. So the facet is analytically zero
  over black on both tiers with no branch for it, which is what the reference's
  `dark-solid` cells measure. The GPU tier reaches the same algebra by emitting
  premultiplied black outside the contour: the readback gains ALPHA and moves no
  RGB channel at all, so what the browser composites is `page × (1 − α)`. The one
  stated residual is the colour SPACE — the reference removes linear light, a
  browser composites encoded sRGB — closed by inverting sRGB's power law
  (`α = 1 − (1−occlusion)^(1/2.4)`), whose worst departure across every backdrop
  level from 0.004 to 1.0 is **2.1 of 255**, against a bed whose own
  reproducibility is ±4/255 (Decision Log 10). The second residual is the blur
  KERNEL: a browser approximates the Gaussian, the shader evaluates it.

  **Accessibility, measured before the fold was written, as the charter
  required.** Reduce-transparency does not remove the shadow and does not deepen
  it: it scales the amplitude to **0.566** (0.1830/0.3259, 0.1884/0.3309,
  0.1882/0.3314 on three backdrops at span 44) with σ, offset and spread
  unmoved. The increased-contrast reference reproduces the reduced-transparency
  amplitude **to four decimals**, which is Decision Log 8 again — macOS
  force-couples the toggles, so the bed cannot separate them and the fold keys on
  `frost`, the axis reduced transparency alone sets. What increased contrast adds
  on top is a hard border stroke one pixel outside the contour (ring-0 occlusion
  0.60–0.80 against a shadow of ~0.10 at ring 1); that is a separate renderer
  feature and the amplitude above is measured on an annulus that excludes it.

  instrument reports the dark profile's shadow as a different SHAPE — upward
  reach collapsing 24 px → 8 px while the downward reach barely moves — and
  recommends a scheme-dependent geometry. Re-tested directly, that is not
  supported: refitting the dark cells with the LIGHT geometry and only the
  amplitude free costs 3–7% of an already-tiny residual (photo capsule RMS
  0.00177 against 0.00165 free; photo rrect-md's own free fit lands on the light
  geometry at σ 15.21, offset 7.29, spread 3.14). One geometry with one amplitude
  per profile predicts the instrument's per-direction extents in all three
  profiles from a single calibration point: light 24/40/32 against a measured
  24/39/32–34, dark 10/26/18 against 8/26/16–20, reduced-transparency 20/36/28
  against 20/35/28–29. The apparent collapse is an iso-occlusion threshold acting
  on a weaker shadow — upward is where the shadow is thinnest, so it crosses
  first. Separately, the falloff is Gaussian rather than exponential: over 585
  points on the 2× photo capsule the Gaussian CDF fits at RMS 0.00233 against the
  exponential's 0.00527. Both are the implementable choice as well as the
  measured one, since `box-shadow` blurs with a Gaussian and takes one alpha.

  **Two field-extent defects, found by the independent review and fixed before
  landing.** Both were on the GPU tier only, and both are the same class: the
  shadow is read from the group's field texture at an OFFSET position, so the
  rect that texture spans has to be right in two different ways.

  The first is the pad's arithmetic. It thresholded the LINEAR occlusion, where
  what the canvas writes is `page × (1 − α·falloff)` in compositing space — so it
  reached about five CSS px further on every edge than anything could be seen at,
  pure cost on a facet already measured at three times frame time. And it was
  taken from the group's BASE amplitude, before the size law amplifies it per
  surface: at a fitted gain the shader would emit more shadow than the pad
  reached and the scissor would slice roughly the last 6 px off, while the CSS
  tier, which has no scissor, went on drawing it. Both are fixed; the pad now
  solves in compositing space against the maximum effective amplitude across the
  group's members, which is an upper bound whatever sign the gain is fitted at.

  The second is a real rendering defect rather than a cost. The shift can leave
  the field texture — for a surface within the shadow's reach of the viewport's
  TOP edge, where the rect is clipped to the canvas, and in the topmost band of
  every group, since the pad is only the reach and the shift needs a further
  offset above that. Clamping repeated the edge texel, which is a distance too
  small, so the falloff went FLAT and too dark exactly where it should have been
  fading out. Reproduced before the fix as a constant alpha of 15 over the seven
  rows above a top-adjacent surface. The shader now adds back the distance it
  could not read, which is exact directly above a surface because a signed
  distance field is 1-Lipschitz, and errs toward less shadow past the corners.
  Pinned by two new GPU e2e scenes — the same surface at the top edge and clear
  of it — asserting the profile is not flat, is monotone, and agrees with the
  unclipped one within one 8-bit code.

  every one of the roughly 5,000 moved pixels per scene moved in ALPHA and moved
  DOWN, which is the only direction either fix can push, at a maximum of 6 codes

  from the changed rect origin. The isolation proof still reproduces `main` on all
  nine scenes with the shadow declined, so the attribution of the whole facet is
  unchanged.

  **The facet is not cheap, and the number is measured rather than estimated.**
  Every GPU pass is confined to the group's field rect, and the shadow's reach
  takes that rect's pad from the rim-and-bulge 3 CSS px to about 41 — several
  times the area on a small control. The benchmark now carries a row for it: the
  same scene at `occlusion: 0`, interleaved, which is the only comparison this
  benchmark trusts. On `apple / metal-3` the shadow costs about **2.8× the
