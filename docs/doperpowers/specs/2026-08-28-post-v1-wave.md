## Purpose

v1 shipped the material with its fidelity claim held to exactly what was
measured: 1× cells, two profiles, a size channel without its laws, no
author-facing tint, and a layer rule stated in prose but enforced nowhere. This
wave widens what the claim covers (the measurement bed first — scale and
accessibility profiles), then closes the three highest-value absences the
coverage matrix ruled as the round's openers (#33(a)), and clears the recorded
seed backlog so the next cut starts clean. The ultimate-goal frame: every child
either widens the measured-fidelity moat (the thing no competitor in the
verified prior art has) or removes a trap a real adopter would hit.

## Parent-Level Acceptance

Observable state that closes the wave as a whole, verified at recomposition in
the shipped artifacts:

1. The fidelity claim covers **2× and both accessibility profiles**: profile
   files and capture matrices exist for the new keys, thresholds are adopted
   and enforced in-suite for them, and the committed 1× matrix is re-baselined
   under recorded capture conditions (its accepted ≤1.5e-4 staleness resolved).
2. A thick and a thin surface over the same backdrop differ the way Apple's
   do: the **size law** couples the material's thickness-derived facets, with
   the coupling fitted against the matrix and holdout-checked.
3. An author can **tint** a surface through a supported API and the result
   remains glass (not flat fill), with a measured claim of its own.
4. Putting glass where the layer model forbids it (glass nested inside
   glass's content) produces a **dev-mode diagnostic naming the rule**, and
   the layer model is documented where an adopter reads.
5. The seed backlog items W6 carries are closed or explicitly re-recorded with
   reasons; `pnpm run ci` and all Playwright suites green; the wave ships as a
   minor release with the demo showing the new capabilities.

## Design

Thin by intake shape — this is an uncoupled bundle; each child designs its own
means. What the joint view settles is graded binding below and in the
contracts.

- **[binding — user ruling 2026-08-28] The reference stays macOS 26.5.** The
  capture machine is this Mac mini (macOS 26.5), driven into a HiDPI scaled
  mode for the 2× keys — the user confirmed the match and chose this over
  updating the Retina MacBook (which runs macOS 15, pre-glass). Every existing
  threshold and fitted constant therefore stays valid; OS 27 reference
  migration stays Deferred.
- **[binding — cut-level ruling] W1 is the bed; W2 and W3 tune only against
  W1's matrix.** Calibration-tuned work against the stale or 1×-only matrix
  would re-create exactly the blind-spot class that produced the corner-hook
  defect (#40).
- **[binding — cut-level ruling] Motion metrics are out of this wave.** The
  native side has no declarative pressed pose; frame sequences need an
  input-driving capture harness that is its own future initiative (Deferred).
- Advisory: the wave probably ships as **0.2.0** at recomposition (new public
  API in W3/W5); a mid-wave patch release is legitimate if W6 lands long
  before the calibration children.

## Risks & Mitigations

- **HiDPI capture ≠ Retina capture.** A scaled mode renders at 2× into a
  panel that downsamples for display; ScreenCaptureKit reads the backing
  store, so captures should be true 2× — but this is exactly what W1's G1
  experiment must prove, not assume. Mitigation: G1 verifies pixel dimensions
  and `backingScaleFactor` from the harness's own probe before any matrix
  run; if the panel's backing store disappoints, the fallback (MacBook on
  macOS 26) returns to the user with the reference-version question attached.
- **Accessibility toggles change the whole desktop.** W1's capture sessions
  announce before flipping display mode or accessibility settings and restore
  after; the harness's refuse-mislabeled-keys guard is the backstop.
- **Two children in one working tree.** X3's re-read rule, plus per-child
  file-scoped commits (`git add` by name, never `-A`).

   profile (2026-08-29; a3b4d00, 5205017).** Measured, not assumed. The native

   force-couples them, and vitrea's two axes are independent media queries, so
